Задача: вы выступаете в роли ML-инженера в кредитном отделе банка. Вам поручено автоматизировать процесс разработки и обслуживания PD-модели. Ваше решение должно быть воспроизводимым, тестируемым и готовым к развёртыванию в продакшн-среде.
Требования к проекту:
1. Организация кода и контроль версий (Git):
   - Создайте структурированный репозиторий на GitHub (например, используя шаблон cookiecutter-data-science).
   - Код должен быть хорошо организован в модули (папки src/, tests/, notebooks/, data/, models/ и так далее).
   - Используйте осмысленные коммиты.
2. Подготовка и валидация данных:
   - Напишите скрипт для загрузки и первичной очистки данных.
   - Реализуйте этап Feature Engineering (например, создание агрегированных признаков из истории платежей, биннинг возраста).
   - Обязательно: используйте Great Expectations или Pandera для создания набора правил (suite) для валидации входящих данных (проверка на наличие null, ожидаемый диапазон значений, типы данных). Напишите тест, который провалится, если в новых данных появятся аномалии.
3. Построение и настройка модели:
   - Разделите данные на тренировочную и тестовую выборки.
   - Создайте Sklearn Pipeline, который включает в себя этапы предобработки (Imputer, Scaler, OneHotEncoder) и обучение модели (например, LogisticRegression или GradientBoostingClassifier).
   - Реализуйте автоматический подбор гиперпараметров с помощью GridSearchCV/RandomizedSearchCV.
   - Обязательно: выведите ключевые метрики качества для задачи бинарной классификации: ROC-AUC, Precision, Recall, F1-Score на отложенной тестовой выборке. Постройте ROC-кривую.
4. Экспериментирование и логирование:
   - Обязательно: интегрируйте MLflow Tracking в ваш код обучения.
   - Записывайте в MLflow: параметры модели, метрики, артефакты (включая графики, такие как ROC-кривая, и саму обученную модель — mlflow.sklearn.log_model).
   - Проведите как минимум пять экспериментов с разными алгоритмами и (или) гиперпараметрами. Проанализируйте результаты в UI MLflow.
5. Контроль версий данных и моделей:
   - Обязательно: инициализируйте DVC в репозитории.
   - Настройте DVC для управления версиями датасета и обученных моделей. Конфигурация должна быть описана в dvc.yaml.
   - Реализуйте DVC-пайплайн как минимум из двух стадий: prepare (подготовка данных) и train (обучение модели).
6. Тестирование (CI):
   - Напишите unit-тесты (с помощью pytest) для ключевых функций вашего кода (например, для функций предобработки, вычисления метрик).
   - Настройте GitHub Actions для автоматического запуска этих тестов и проверки качества кода (линтинг с flake8 и форматирование с black) при каждом пуше в репозиторий.
   - Обязательно: включите в CI-пайплайн шаг, который запускает валидацию данных с помощью Great Expectations.
7. Контейнеризация и развёртывание:
   - Напишите Dockerfile для создания образа вашего приложения. Образ должен содержать все зависимости для запуска обучения или инференса.
   - Обязательно: реализуйте простой REST API для модели с помощью FastAPI. API должен иметь endpoint /predict, который принимает JSON с признаками и возвращает предсказание (класс и вероятность).
   - Напишите скрипт для билда докер-образа и его запуска локально. Убедитесь, что API работает.
8. Мониторинг (CD):
   - Задание повышенной сложности: напишите простой скрипт на Python, который имитирует поступление новых данных (берёт часть тестовой выборки) и отправляет их на ваш API. Скрипт должен рассчитывать метрики дрифта данных (например, Population Stability Index (PSI) для распределения вероятностей или для ключевых признаков) при сравнении с тренировочными данными.
9. Документация и итоги:
   - Создайте понятный README.md, который описывает проект, его структуру и инструкции по запуску.
